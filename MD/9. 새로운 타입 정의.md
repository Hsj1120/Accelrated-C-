# 9. 새로운 타입 정의

C++의 타입은 기본 타입과 클래스 타입으로 나눌 수 있다.

기본 타입은 프로그래밍 언어의 기본 영역에 정의되어 있으며 char, int, double 등이 있다.

반면 라이브러리를 이용한 타입인 문자열, 벡터, istream등은 모두 클래스 타입이다.

C++에서 설계한 기능 대부분은 기본 타입을 이용하여 손쉽게 프로그래머가 새로운 타입을 만들 수 있게 하자는 개념을 기초로 한다.

9장에서는 기본적인 클래스의 정의 기능을 살펴보자



## 9.1 Student_info 살펴보기

4.2.1에서는 학생들의 과목 점수를 다루는 프로그램을 쉽게 작성하려고 Student_info라는 데이터 구조와 함수를 만들었다.

하지만 이렇게 만든 구조는 다른 프로그래머사 사용하기에 적합하지 않다.

우리가 작성한 함수를 사용하려는 프로그램은 특정 규칙을 따라야 한다. 예를 들어 새로 만든 Student_info 객체를 사용하려면 먼저 데이터를 읽어 들어야 한다. 그렇지 않으면 빈 homework 벡터와 정의하지 않는 값이 할당된 midterm과 final이 있는 객체가 만들어지는데, 이런 객체를 사용하면 부정확한 결과를 얻거나 갑작스러운 충돌이 일어날 수 있다.

또한 기존 Student_info에 관한 '인터페이스'가 흩어져 있다. 기존 방법처럼 read 함수 같은, Student_info 객체의 상태를 바꾸는 함수를 하나의 헤더파일에 넣을 수 있다. 하지만 이러한 방법은 선택사항이며 그룹화를 위한 요구사항은 존재하지 않는다.



## 9.2 클래스 타입

클래스 타입은 연관된 데이터 값을 데이터 구조에 결합한 상태이다. 해당 데이터 구조는 독립적이다. 예를 들어 Student_info 구조체는 Student_info 타입 객체를 정의하고 조작할 수 있다.

```c++
struct Student_info {
	std::string name;
	double midterm, final;
	std::vector<double> homework;
};
```

Student_info 타입의 각 객체에는 4가지 요소가 있다. Student_info 타입을 사용하는 프로그래머는 이러한 데이터 요소를 직접 조작해야 한다.

Student_info 정의에서 데이터 요소에 접근을 제한하지 않으므로 프로그래머는 데이터를 직접 조작할 수 있다.

Student_info 타입을 사용하는 프로그래머가 직접 데이터에 접근하는 것을 허용하지 않도록 구현 사항을 숨길 수 있다. 특히 함수로만 객체에 접근하도록 만들 수 있다.

그러려면 먼저 Student_info 객체를 조작하기에 적합한 함수를 사용자에게 제공해야 한다. 이 함수는 클래스의 인터페이스를 구성하게 된다.



### 9.2.1 멤버 함수

Student_info 객체의 접근을 제어하려면 프로그래머가 사용할 수 있는 인터페이스를 정의해야 한다. 우선 정보를 읽는 동작과 최종 점수를 구하는 동작을 정의해보자.

```c++
struct Student_info {
	std::string name;
	double midterm, final;
	std::vector<double> homework;

	std::istream& read(std::istream&);
	double grade() const;
};
```

4개의 데이터 요소가 있으며, 2개의 멤버함수를 추가하였다.

이러한 멤버 함수를 사용하면 입력 스트림에서 정보를 읽어 Student_info 객체의 최종적으로 구할 수 있다.



1.2에서 문자열 클래스의 멤버 함수인 size를 사용하여 멤버 함수를 처음 다루었다. 기본적으로 멤버 함수는 클래스 객체의 멤버인 함수이다. 멤버 함수를 호출하려면 해당 함수를 멤버로 갖는 객체를 반드시 지정해야 한다.

즉, greeting이라는 문자열 객체에 greeting.size()를 호출하는 것과 비슷하게 s라는 Student_info 객체에 s.read(cin) 또는 s.grade()를 호출한다.



첫번째로 살펴볼 멤버 함수의 정의는 4.2.2에서 다룬 read 함수의 원 버전과 비슷하다.

```c++
istream& Student_info::read(istream& is)
{
	is >> name >> midterm >> final;
	read_hw(is, homework);
	return is;
}
```

이 read와 기존 read 함수 사이에 차이점이 3가지가 있다.

1. 함수 이름이 read가 아니라 Student_info::read이다
2. 이 함수는 Student_info 객체 멤버이므로 Student_inf 객체를 인수로 전달하거나 Student_info 객체를 정의할 필요가 없다.
3. 이 함수에는 Student_info 객체의 데이터 요소에 직접 접근한다.

지금 부터 이러한 차이점을 살펴보자

함수 이름의 ::은 범위 연산자이다. 표준 라이브러리가 정의한 이름에 접근하는데 사용된다. 예를 들어 문자열 클래스의 멤버은 size_type이라는 이름에 접근하려면 string::size_type이라고 작성하듯이 Student_info 타입의  멤버인 read함수를 정의하려고 Student_info::read라고 작성한다.



이 멤버함수는 istream&타입의 매개변수 하나만 있으며 Student_info&타입의 매개변수는 모든 호출에 암묵적으로 존재한다. 즉 멤버함수는 자기 자신이 누구 객체 소속인지 자동으로 알고 있다.

Student_info 객체의 멤버인 read함수를 호출하려면 Student_info 객체를 명시해야 한다. 해당 객체는 read 함수에서 암묵적으로 사용된다.



read 함수 내부에서 객체는 이름을 명시하지 않고 멤버를 참조할 수 있다. 이유는 현재 다루는 객체의 멤버를 참조하는 것이기 때문이다.

다시 말해 Student_info 객체 s에 s.read(cin)을 호출한다면 객체 s에 관한 동작을 실행한다.

read 함수가 midterm, final, homework를 사용한다면 각각 s.midterm, s.final, s.homework를 사용한다.



grade 함수를 살펴보자

```c++
double Student_info::grade() const
{
	return ::grade(midterm, final, homework);
}
```

이 함수는 4.2.2에서 살펴본 grade 함수와 비슷하다.

차이점은 grade 함수 매개변수 목록 다음에 const를 사용하는 것인데 기존 grade 함수와 비교해보면

```c++
double Student_info::grade() const // 멤버 함수 버전
double grade(const Student_info&) // 4.2.2에서 살펴본 기본 버전
```

기존 grade 함수에서는 Student_info 객체의 참조 타입을 const로 전달한다. 이를 사용해 const Student_info 객체의 최종 점수를 구할 수 있고 grade 함수가 매개변수를 바꾸려 시도하면 컴파일러는 문제가 있음을 알린다.

멤버 함수를 호출할 때는 해당 멤버 함수를 포함하는 객체를 인수로 전달하지 않으므로 매개 변수 목록에는 객체가 const임을 명시할 수 있는 항목이 없다. 대신 함수 자체의 의미를 무여하여 const 멤버함수로 만든다. 

const 멤버 함수는 동작을 실행 중인 객체의 내부 상태를 바꿀 수 없다. 예를 들어 s가 Student_info 객체일 때 s.grade()를 호출하면 s의 데이터 멤버를 바꿀수 없다.

const 멤버 함수는 객체 값을 바꾸지 않으므로 const 객체를 다루는데 호출할 수 있다.

마찬가지로 const 객체를 다룰 때 const가 아닌 함수는 호출할 수 없다. 예를 들어 const Student_info 객체를 다룰 때 read 멤버 함수는 호출할 수 없다.

결국 read와 같은 함수는 객체의 상태를 바꿀 수 있다는 의미이다. const 객체를 다룰 때 const가 아닌 함수를 호출하면 const를 사용해서 보장해야하는 값 변경 없음이라는 약속을 어길 수 있다.



주의해야 할 점은 프로그램이 const 객체를 반드시 직접 만들지 않더라도 함수의 호출로 const 객체를 참조할 수 있다는 것이다.

const 참조 타입이 매개변수로 있는 함수에 const가 아닌 객체를 전달하면 함수는 해당 객체를 const인 것처럼 취급한다. 그리고 컴파일러는 해당 객체의 const 멤버 함수의 호출만 허용한다.

즉 수정 가능한 객체를 전달하더라도, const 참조로 받는 함수 안에서는 그 객체를 잠깐 읽기 전용처럼 사용한다.



## 9.2.2 멤버가 아닌 함수

`read`와 `grade`는 객체 자기 자신을 다루는 함수라서 멤버 함수로 만들었다. 그렇다면 `compare`도 멤버 함수로 만들어야 할까?

C++에서는 어떤 함수들은 반드시 멤버 함수여야 하지만, `compare`는 그런 경우가 아니다.  그래서 멤버 함수로 만들어도 되고, 일반 함수로 만들어도 된다.

보통 객체의 상태를 바꾸는 함수라면 멤버 함수로 만드는 것이 자연스럽다.

하지만 `compare`는 객체를 바꾸지 않는다.  단지 두 Student_info 객체를 비교해서 누가 더 작은지 판단할 뿐이다.

즉 `compare`는 특정 객체 하나의 행동이라기보다, 두 객체 사이의 관계를 처리하는 함수에 가깝다.

그래서:

```
a.compare(b)
```

보다는:

```
compare(a, b)
```

처럼 사용하는 것이 더 자연스럽다.

따라서 `compare`는 클래스 안의 멤버 함수가 아니라, 클래스 밖의 일반 함수(global function)로 두겠다.



## 9.3 보호 레이블

grade 함수와 read 함수를 멤버 함수로 정의해 문제점을 어느 정도 개선 했다.

이번엔 데이터를 숨기고 Student_info 타입을 사용하는 프로그래머가 멤버 함수를 이용해서만 데이터에 접근할 수 있도록 만들어 보자

C++는 타입의 작성가자 해당 타입의 멤버를 public으로 명시하여 타입을 사용하는 모든 프로그래머가 접근할 수 있도록 만든다. private으로 명시하면 데이터를 숨겨서 타입을 사용하는 프로그래머가 접근할 수 없게 만든다.

```c++
class Student_info {
public:
	std::istream& read(std::istream&);
	double grade() const;
private:
	std::string name;
	double midterm, final;
	std::vector<double> homework;
};
```

struct대신 class를 사용했고 2개의 **보호 레이블**를 추가했다. 각 보호 레이블은 뒤에 따르는 모든 멤버의 접근 방식을 정의한다.

private 레이블 뒤에 name, homework, midterm, final을 작성하면 Student_info 타입을 사용하는 프로그래머가 이러한 데이터 요소에 접근할 수 없도록 막는다. 

public 레이블에 해당하는 멤버는 모두 사용할 수 있다. 즉 Student_info 타입을 사용하는 모든 프로그래머가 read함수와 grade 함수를 호출할 수 있다.



### 9.3.1 접근자 함수

지금까지는 데이터 멤버를 숨겨 프로그래머가 객체의 데이터를 바꿀 수 없게 했다. 대신 read 함수를 사용하여 데이터 멤버를 설정하고 grade 함수를 사용해 주어진 Student_info 객체의 최종 점수를 구해야 한다.

그리고 프로그래머에게 핵상의 이름을 알려주어야 한다.

다음 처럼 구현할 수 있다.

```c++
class Student_info {
public:
	double grade() const;
	std::istream& read(std::istream&);
	std::string name() const { return n; }
private:
	std::string n;
	double midterm, final;
	std::vector<double> homework;
};
```

읽기 전용 함수인 name함수를 추가하였다.

name 함수는 인수가 없으며 n을 복사한 문자열을 반환하는 const 멤버 함수이다.n을 참조하지 않고 복사해서 클래스를 사용하는 프로그래머가 n 값을 읽을 수는 있지만 바꿀 수는 없다.



name 함수를 추가했으므로 이제 compare 함수를 다시 작성할 수 있다.

```c++
bool compare(const Student_info& x,	const Student_info& y)
{
	return x.name() < y.name();
}
```

4.2.2에  버전과 비슷하지만 한 가지 차이점을 학생 이름을 얻는 방식이다. 기존 버전에서는 데이터 멤버에 직접 접근할 수 있었지만 지금은 name 함수를 호출해야 한다. `compare`는 Student_info 클래스 안에 들어있는 함수는 아니지만,
 Student_info를 사용할 때 같이 필요한 함수이기 때문에 헤더파일에 선언해서 사용자에게 공개해줘야 한다



## 9.3.3 벡터가 비어 있을 때

멤버를 숨기고 알맞은 접근자 함수를 제공했다면 이제 남은 문제는 한 가지이다. 클래스를 사용하는 프로그래머가 객체의 데이터를 직접 봐야할 문제이다. 예를 들어 read 함수를 호출하지 않은 객체에 grade 함수를 호출하면 어떤 일이 발생하는 지 살펴 보자

```c++
Student_info s;
cout << s.grade() << endl; // 예외: s에는 데이터가 없음
```

read 함수 호출로 s에 값을 부여하지 않았으므로 s의 멤버인 homework는 비어있을 것이고 grade 함수를 호출하면 예외를 던진다. catch문을 사용해 예외를 처리할 수 있지만 문제 발생을 사전에 감지할 수 없으므로 grade 함수의 호출을 피할 수 없다.

4장에서 다룬 기존의 Student_info 구조체를 사용할 때는 프로그래머가 homework 멤버를 검사하여 grade 함수를 정상적으로 호출할 수 있는지 결정할 수 있었다. 만약 homework가 비어 있다면 grade 함수를 호출하지 않았다. 이 접근법은 효과적이었지만 프로그래머가 homework를 검사하려면 객체의 구조를 반드시 알아야 했다. 다음과 같이 더 추상적인 형태로 같은 검사를 한다면 효과적이다.

```c++
class Student_info{
public:
    bool valid() const {return !homework.empty();}
    // 중략
}
```



### 9.4 Student_info 클래스

기존의 Student_info 구조체에 제기한 문제들을 대부분 해결햇으므로 지금까지 살펴본 것들을 종합해 코드로 나타내 보자

```c++
class Student_info {
public:
	std::string name() const { return n; }
	bool valid() const { return !homework.empty(); }

	// 9.2.1에서 정의한 read 함수에서 name을 n으로 변경 필요
	std::istream& read(std::istream&);

	// 9.2.1 에서 정의한 것과 같음
	double grade() const;
	
private:
	std::string n;
	double midterm, final;
	std::vector<double> homework;
};

bool compare(const Student_info&, const Student_info&);
```



### 9.5 생성자

객체가 만들어 질 때 어떤 일이 일어날지 생각해 보자

라이브러리는 라이브러리 클래스의 객체를 만들 때 해당 객체가 적절한 값이 있도록 보장한다.

예를 들어 초깃값 없이 문자열이나 벡터를 정의하면 빈 문자열이나 빈 벡터를 얻는다. 또한 문자열과 벡터의 새로운 객체를 정의할 때 크기 또는 채울 문자와 개수를 지정하여 초기값을 부여할 수 있다.

**생성자**는 객체를 초기화하는 방식을 정의하는 특수한 멤버 함수이다. 생성자를 명시적으로 호출할 수 있는 방법은 없다. 대신 클래스 타입의 객체를 만들면 부수적으로 알맞는 생성자를 자동으로 호출한다.

생성자를 정의하지 않았다면 컴파일러는 합성한 생성자를 제공한다. 이는 11.3.5에서 다룬다. 지금은 생성자를 정의하지 않으면 어떤 일이 벌어지는지 살펴보자. 이 떄 프로그래머는 Student_info 객체를 정의할 수 있지만 다른 Student_info 객체의 복사본을 할당하는 것 외에는 명시적으로 초기화할 수는 없습니다.

합성한 생성자는 데이터 멤버를 초기화하며 이 때 값은 객체를 만드는 방식에 따라 다르다. 만약 객체가 지역 변수라면 데이터 멤버는 **기본초기화**방식을 따르고, 만약 객체가 맵에 새로운 요소를 추가할 때나 크기가 지정된 컨테이너 요소로 초기화하는데 사용되면 데이터 멤버는 **값 초기화** 방색일 따른다. 이러한 규칙은 복잡하지만 핵심은 다음과 같다.

- 객체가 하나 이상의 생성자를 정의하는 클래스 타입이면 적절한 생성자가 해당 클래스의 객체 초기화 과정을 제어한다.
- 객체가 기본 타입이면 '값 초기화' 방식에서 0으로 설정하고 '기본 초기화' 방식에서는 정의되지 않은 값을 부여한다.
- 앞 두 상황에 해당하지 않으면  객체는 생성자를 정의하지 않은 클래스 타입일 수 밖에 없다. 이 때 객체를 '값 초기화' 또는 '기본 초기화'된다. 데이터 멤버 중 자체 생성자가 있는 클래스 타입이 있을 때는 이러한 초기화 과정이 되풀이 된다.

여기서 Student_info 클래스는 3번째에 해당한다. Student_info는 클래스 타입이며 객체를 만드는 방법을 명시하지 않았다.

따라서 Student_info 타입의 지역 변수를 정의할 때 n 멤버와 homework 멤버는 생성자가 있는 클래스 객체이므로 각각 빈 문자열과 빈 벡터로 자동 초기화 된다. 반대로 midterm과 final은 기본초기화 되어 정의되지 않는 값 즉 쓰래기 값을 같는다.

방금 살펴본 동작에는 문제가 없어 보일 수 있다. 멤버에 값을 할당하는 read 함수를 호출하여 먼저 객체를 초기화 하지 않고서야 midterm이나 final 값을 사용할 일은 없기 때문이다.

하지만 일반적으로 모든 데이터 멤버가 항상 타당한 값이 있도록 보장하는 것이 좋다. 예를 들어 나중에 우리나 코드의 유지보수를 맡은 다른 프로그래머가 이러한 데이터 멤버를 다루는 연산을 추가할 수 있기 때문이다.

결국 생성자로 데이터 멤버를 초기화 하지 않으면 나중에 새롭게 추가될 연산 때문에 오류가 발생할 수 있다. 그래서 초기화를 해야 한다.



2개의 생성자를 정의할 것이다. 첫번째 생성자는 인수가 없는 빈 Student_info 객체를 만든다. 두번째 생성자는 입력 스트림의 참조를 인수로 갖고 해당 스트림에서 학생 정보를 읽어 객체를 초기화 한다.

이를 바탕으로 Student_info 타입을 사용하는 프로그래머는 다음과 같은 코드를 작성할 수 있다/

```c++
Student_info s; // 빈 Student_info
Student_info s2(cin) // cin을 읽어 s2 초기화
```

생성자가 다른 멤버함수들과 구별되는 점은 2가지 이다. 생성자는 클래스 이름과 같은 이름을 갖고 반환 타입이 없다. 생성자가 다른 함수들과 비슷한 점은 인수의 개수와 타입에 따라 다양한 버전의 생성자를 정의할 수 있다는 것이다.

이를 바탕으로 2개의 생성자를 추가하여 클래스를 수정해 보자

```c++
class Student_info {
public:
	Student_info(); // 빈 Student_info 객체를 생성
	Student_info(std::istream&); // 스트림을 읽어서 Student_info 객체를 생성
```



### 9.5.1 기본 생성자

인수가 없는 생성자를 **기본 생성자**라고 한다. 객체의 데이터 멤버가 적절하게 초기화 되도록 보장하는 역할이다.

Student_info 객체라면 아직 학생정보를 읽지 않았음을 나타내도록 데이터를 초기화 해야 한다. 다음 코드로 homework 멤버는 빈 벡터, n은 빈 문자열, midterm과 final은 0으로 초기화 할 수 있다.

```c++
Student_info::Student_info() : midterm(0), final(0) {}
```

이 생성자는 새로운 문법을 사용한다. ':'과 '{' 사이에는 각 괄호 사이에 있는 값으로 해당 멤버를 초기화 하도록 컴파일러에게 지시하는 **생성자 이니셜라이저**가 나열되어 있다. 따라서 앞 기본 생성자는 midterm과 final에 명시적으로 0을 할당하도록 동작한다.

함수 본문이 비어 있으므로 생성자는 표면적으로 다른 동작을 실행하지 않으며 앞으로 삺보겠지만 n과 homework는 암묵적으로 초기화 된다.

클래스 객체를 새로 만들면 다음 과정이 차례로 일어난다.

1. 구현체는 객체를 담을 메모리를 할당한다.
2. 이니셜 라이저 목록에 명시한 초깃값으로 객체를 초기화 한다.
3. 생성자의 본문을 실행한다.

구현체는 이니셜 라이즈 목록의 순서와 상관없이 정의에 명시한 순서대로 데이터 멤버를 초기화 한다.

이때 목록에 언급되지 않응 멤버가 있더라고 모든 멤버를 초기화 한다. 이어서 생성자 본문에서 이러한 초기값을 바꿀 수 있다. 그러나 본문을 실행하기 전에 초기화를 한다.

생성자 본문에서 값을 할당하지 않고 그 전에 초기화해 같은 동작을 두 번 반복 실행하는 것을 피할 수 있습니다.



앞서 언급한 바에 따르면 객체가 적절하게 초기화된 데이터 멤버가 있는 상태에서 만들어지는 것을 보장하려고 생성자가 존재한다. 일반적인 이러한 설계 목표는 모든 생성자가 모든 멤버를 초기화 해야한다는 걸 의미한다.

여기서 midterm과 final만 명시적으로 초기화 했고 다른 멤버들은 암묵적으로 초기화된다. 구체적으로 n은 문자열 클래스의 기본 생성자를 이용해 초기화 되고 homework는 벡터 클래스의 기본 생성자를 이용해 초기화 한다.



### 9.5.2 인수가 있는 생성자

Student_info 클래스의 두번째 생성자는 훨씬 이해하기 쉽다

```c++
Student_info::Student_info(std::istream& is) { read(is); }
```

이 생성자는 실제 동작을 read 함수에게 맞긴다. 생성자에 이니셜라이저를 명시하지 않았으므로 homework와 n 멤버는 각각 벡터 클래스와 문자열 클래스의 기본 생성자를 이용해 초기화 된다. midterm과 final 멤버는 객체가 '값 초기화'될 때만 명시적인 초깃값이 있다.

이와 같은 부실한 초기화는 문제가 되지 않는데 왜냐면 read 함수가 이러한 변수에 새로운 값을 즉시 부여하기 때문이다.

## 9.7 핵심 정리

**사용자 정의 타입**

 struct 또는 class로 정의할 수 있다. 둘의 유일한 차이는 첫 번째 접근 지정자 이전에 정의된 멤버의 기본 접근 권한이다. struct 뒤에 정의된 멤버는 기본적으로 public이고, class 뒤에 정의된 멤버는 기본적으로 private이다.

**접근 지정자**

 클래스 타입의 멤버에 대한 접근을 제어한다. public 멤버는 일반적으로 어디서나 접근 가능하고, private 멤버는 클래스의 멤버만 접근할 수 있다. 접근 지정자는 클래스 안에서 여러 번 사용할 수 있으며 순서도 자유롭다.

**멤버 함수** 

타입은 데이터뿐만 아니라 멤버 함수도 정의할 수 있다. 멤버 함수는 특정 객체를 대신하여 암묵적으로 호출된다. 멤버 함수 안에서 멤버 데이터나 멤버 함수를 참조하면 자동으로 해당 객체에 연결된다.

멤버 함수는 클래스 정의 내부나 외부에서 정의할 수 있다. 클래스 내부에서 멤버 함수를 정의하면 구현체가 해당 함수를 inline 형태로 확장하도록 요청하는 것이며, 이를 통해 함수 호출 오버헤드를 줄일 수 있다. 클래스 외부에서 정의할 때는 함수 이름이 클래스 범위에 속한다는 것을 나타내기 위해 범위를 지정해야 한다. class-name::member-name 형태는 class-name 클래스의 member-name 멤버를 의미한다.

멤버 함수는 매개변수 목록 뒤에 const 키워드를 붙여 const 함수로 정의할 수 있다. 이러한 함수는 호출된 객체의 상태를 변경할 수 없다. const 객체에서는 const 멤버 함수만 호출할 수 있다.

**생성자**

 타입 객체가 어떻게 초기화될지를 정의하는 특별한 멤버 함수이다. 생성자는 클래스와 같은 이름을 가지며 반환값이 없다. 클래스는 인자의 개수나 타입이 다르다면 여러 생성자를 정의할 수 있다. 일반적으로 모든 생성자는 종료될 때 모든 데이터 멤버가 적절한 값을 가지도록 만드는 것이 좋다.

**생성자 초기화 리스트**

생성자 초기화 리스트는 member-name(value) 형태의 쌍들을 쉼표로 나열한 것이다. 각 member-name은 대응되는 값으로 초기화된다. 명시적으로 초기화하지 않은 데이터 멤버는 암묵적으로 초기화된다.

멤버가 초기화되는 순서는 생성자 초기화 리스트 순서가 아니라 클래스 안에서 선언된 순서에 따라 결정된다. 따라서 한 멤버를 사용해 다른 멤버를 초기화할 때는 주의해야 한다. 이런 상호 의존성을 피하기 위해 생성자 초기화 리스트에서 초기화하기보다는 생성자 본문 안에서 값을 대입하는 것이 더 안전한 방법이다.
